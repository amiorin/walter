# Plan: adapt Once validation to Walter

Status: implemented in this checkout. Verification run:

- `clojure -M:test`
- `bb run package validate` with placeholder defaults (expected validation failure)
- `bb run package validate` with no-infra `BC_PAR_COMPUTE_PUBKEY` and `BC_PAR_NO_INFRA_COMPUTE_IP` overrides (passed)
- `bb run tofu render` with `BC_PAR_PROVIDER_BACKEND=r2` and stub R2 params (rendered R2 backend)

## Goal

Create a Walter-specific equivalent of `/home/ubuntu/code/bigconfig/once/clojure/src/clj/io/github/bigconfig_ai/once/validation.clj` so users can validate the active Walter profile before `bb run package create`.

Target outcome:

- `bb run package validate` prints a grouped report and exits non-zero on failure.
- No top-level `bb run validate` shortcut for Walter.
- Validation runs live checks by default, like Once.
- Validation is testable through pure report builders with injectable process/env seams.

## Decisions

- CLI surface: only `bb run package validate`.
- Validation depth: schema + tools + live credential/API checks, matching Once.
- `no-infra`: behave like Once — validate params, but do not attempt SSH connectivity.
- SSH-agent readiness: update Walter to use `:compute-pubkey`, then reuse Once-style ssh-agent validation for cloud compute providers.
- Backend support: ensure Walter supports `r2` like Once.
- Ansible data: include Walter-specific sanity checks.

## Current findings

- Walter currently has package steps: `build`, `create`, `delete` only.
- `io.github.bigconfig-ai.walter.package/walter` does not wire `::workflow/validate-fn` yet.
- `io.github.bigconfig-ai.walter.cli/package-commands` does not include `validate`.
- Walter reuses Once `tofu` / `ansible-local` tools and `once.params/tofu-params` for compute params.
- Walter has no `test/` suite yet.
- Walter `deps.edn` does not directly declare `metosin/malli` or `babashka/process`; Once validation uses both.
- Walter params are narrower than Once params: no SMTP/DNS/domain/applications/image validation, but compute/backend/profile/package validation still applies.
- Walter currently hardcodes an Ansible authorized SSH key in `ansible.clj`; this should move to `:compute-pubkey`.

## Proposed implementation

### 1. Add a Walter validation namespace

Create `src/clj/io/github/bigconfig_ai/walter/validation.clj`, adapted from Once validation.

Keep the same high-level shape:

- `validate-report` — pure-ish entry point returning `{:ok? boolean :errors [...]}`.
- `schema-errors` — Malli schema validation for active profile params.
- `tool-errors` — PATH checks with injectable `which-fn`.
- `credential-errors` — live credential checks with injectable env/process seams.
- `ansible-data-errors` — Walter-specific sanity checks for rendered Ansible data.
- `validate` — big-config workflow step that prints grouped output and sets `::bc/exit` / `::bc/err`.

Remove Once-only checks:

- SMTP provider schemas and Resend checks.
- DNS provider schemas and Cloudflare zone checks.
- `:domain`, `:once :applications`, image format checks, and `skopeo inspect`.
- Deploy key checks.

### 2. Update Walter to use `:compute-pubkey`

Add `:compute-pubkey` to Walter profile params in `run` and `options.clj`.

Use `:compute-pubkey` as Walter's automation/user authorized key:

- In `ansible.clj`, derive `config :ssh_key` from `:compute-pubkey` instead of the current hardcoded key.
- Keep provider-specific fields that cloud APIs still need (`hcloud-ssh-keys`, `digitalocean-ssh-keys`, `oci-ssh-authorized-keys`) unless/until templates are changed to derive them from the public key.
- Validation should require `:compute-pubkey` to look like an SSH public key.
- For cloud compute providers (`oci`, `hcloud`, `digitalocean`), validate that `:compute-pubkey` is loaded in `ssh-agent`, matching Once.
- For `no-infra`, skip the ssh-agent check, matching Once.

### 3. Walter schema scope

Validate the active profile contains:

- `::render/profile` — non-empty string.
- `::workflow/params :package` — non-empty string.
- `::workflow/params :compute-pubkey` — SSH public key string.
- `:provider-compute` — one of `oci`, `hcloud`, `digitalocean`, `no-infra`.
- `:provider-backend` — one of `s3`, `r2`, `local`.
- `:compute-prevent-destroy` — optional boolean.

Compute provider params:

- `oci`: `oci-config-file-profile`, `oci-subnet-id`, `oci-compartment-id`, `oci-availability-domain`, `oci-display-name`, `oci-shape`, integer sizing fields, `oci-ssh-authorized-keys`.
- `hcloud`: `hcloud-name`, `hcloud-image`, `hcloud-server-type`, `hcloud-location`, `hcloud-ssh-keys`, `hcloud-token`.
- `digitalocean`: `digitalocean-name`, `digitalocean-region`, `digitalocean-size`, `digitalocean-image`, `digitalocean-vpc-uuid`, `digitalocean-ssh-keys`, `do-token`.
- `no-infra`: `no-infra-compute-ip`, `no-infra-compute-user`, `no-infra-compute-sudoer`, `no-infra-compute-uid`.

Backend provider params:

- `s3`: `s3-bucket`, `s3-region`.
- `r2`: `r2-bucket`, `r2-endpoint`, `r2-access-key-id`, `r2-secret-access-key`.
- `local`: no extra params.

All required string fields should reject blank strings and `REPLACE_ME` placeholders.

### 4. Ensure R2 backend support matches Once

Walter already passes backend params through Once's Tofu tooling path, but confirm generated `.dist/.../tofu` includes backend rendering for `r2` exactly as Once does.

Validation should include:

- R2 schema fields.
- AWS CLI requirement for `r2`.
- `aws s3api head-bucket --bucket <r2-bucket> --endpoint-url <r2-endpoint>` with `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION=auto`.
- Same missing-bucket vs bad-credentials classification as Once.

### 5. Tool checks

Base tools:

- `tofu`
- `ansible-playbook`
- `ssh`
- `curl`

Provider/backend tools:

- `oci` when `:provider-compute` is `oci`.
- `hcloud` when `:provider-compute` is `hcloud`.
- `doctl` when `:provider-compute` is `digitalocean`.
- `aws` when `:provider-backend` is `s3` or `r2`.

Do not require `skopeo` for Walter.

### 6. Credential checks

Reuse/adapt Once helpers where applicable:

- `hcloud-token`: `curl` bearer check against Hetzner Cloud API.
- `do-token`: `curl` bearer check against DigitalOcean API.
- `oci`: check OCI config file exists and `oci iam region list --output json` succeeds when OCI CLI is available.
- `s3`: run `aws sts get-caller-identity` when AWS CLI is available.
- `r2`: run `aws s3api head-bucket --bucket ... --endpoint-url ...` with supplied R2 env vars and classify missing bucket vs auth failure.
- Cloud compute providers: verify `SSH_AUTH_SOCK` is set and `ssh-add -L` contains `:compute-pubkey`.
- `no-infra`: no SSH connectivity check and no ssh-agent check.

### 7. Walter Ansible data sanity checks

Add validation for data returned by `io.github.bigconfig-ai.walter.ansible/data-fn` after params/env overrides are applied.

Initial checks:

- At least one host exists and each host is non-placeholder.
- Users have non-empty `:name` and `:uid`.
- Active users include the expected main user (`ubuntu` for current defaults).
- `config :ssh_key` is present, non-placeholder, and matches `:compute-pubkey`.
- Repos have non-empty `:org`, `:repo`, `:branch`, and `:user`.
- Packages have non-empty package name and CLI name.

Report these under a new `:ansible-data` group.

### 8. Wire into package workflow and CLI

- Require `io.github.bigconfig-ai.walter.validation` in `package.clj`.
- Add `::workflow/validate-fn validation/validate` to the opts merged by `walter`.
- Add `validate` to `package-commands` in `cli.clj`.
- Update help text with `bb run package validate`.
- Do not add a top-level `bb run validate` shortcut.

### 9. Dependencies

Add direct dependencies if the new namespace requires them:

- `babashka/process`
- `metosin/malli`

`cheshire` is already present.

### 10. Tests

Add Walter validation tests modelled on Once validation tests.

Suggested path/convention:

- Use `test/clj/io/github/bigconfig_ai/walter/validation_test.clj`.
- Update `deps.edn :test :extra-paths` from `["test"]` to `["test/clj"]`, unless we prefer to keep tests directly under `test/io/...`.

Test coverage:

- Public/default profiles pass schema after replacing placeholders with stub values, including `:compute-pubkey`.
- `REPLACE_ME` placeholders are reported.
- Missing required params are reported.
- Provider tool selection returns expected CLIs.
- `tool-errors` honors injected `which-fn`.
- Workflow step sets exit status and stores `::validation/result`.
- R2 error classification is covered.
- OCI/HCloud/DigitalOcean credential checks are covered via `with-redefs` for process runner.
- ssh-agent checks mirror Once for cloud compute and skip `no-infra`.
- Ansible data checks catch missing/placeholder `:compute-pubkey` and malformed users/repos/packages.
- CLI accepts `package validate` and rejects bare `validate` with guidance to use `bb run package validate`.
